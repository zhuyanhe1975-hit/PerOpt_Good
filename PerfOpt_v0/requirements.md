# Requirements: PerfOpt（最小可运行主线）

## 1. 项目定位
PerfOpt 面向 ER15-1400 工业机器人：在统一“前馈补偿 + 轨迹规划 + 反馈控制”的框架下，通过可解释的快/准/稳权重，搜索不同工况的 Pareto 最优参数组合。

## 2. v0（当前主线）交付边界：先跑起来，再变强
必须具备：
- CPU + MuJoCo 仿真评估（ER15 MJCF）。
- 统一控制器：6 关节独立 PID + 逆动力学前馈（ff_mode 四档：no/ref/meas/ideal）。
- 统一指标输出（JSON）：节拍/误差/振动/能耗（proxy）+ 力矩统计。
- 统一 loss：快/准/稳/能耗加权（支持 baseline 归一化，避免量纲不一致）。
- Optuna 调度器：支持单进程与多进程并行（sqlite storage + dashboard）。
- 最小可视化：仅在“非优化运行/优化结束回放”打开 MuJoCo viewer。
- 对比工具：compare-ff（4 模式 TCP 误差 + 力矩曲线 + JSON）。

暂不做（保持最小化）：
- MJX/JAX/GPU 动力学后端（mujoco_warp 等仅做环境验证，不进入主线）。
- 在线辨识（摩擦/刚度/载荷）、复杂三环/完整 jerk 规划器、真实电机/驱动模型。

## 3. 指标定义（v0）
- cycle_time：轨迹完成时间（s）。
- e_max：TCP 位置误差最大值（m）。
- rmse：TCP 位置误差均方根（m）。
- vib_energy：由 TCP 加速度幅值 FFT 得到的频带能量（无量纲 proxy，便于相对比较）。
- energy：简化能耗 proxy（当前随 dt 变化明显；仅用于同 dt 相对比较）。
- torque_max/min/mean：仿真过程中关节力矩统计（单位取决于 MuJoCo 模型，通常为 N·m）。

## 4. 约束与默认假设（v0）
- 参考轨迹必须“数值友好”：优先余弦位移（t=0 速度为 0）+ 整数周期；并基于速度上限/关节限位裁剪幅值。
- 约束（主线）：关节限位、速度上限、力矩限幅（工程模式）；ideal 模式可禁用限幅用于“理论上限”对照。
- MJCF 接触/自碰是误差的高风险来源：优先保证无自碰可控环境跑通，再逐步回归真实接触。
